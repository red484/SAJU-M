# 달빛 사주 v3

달빛 산수화 첫 화면을 유지하고, 만세력·결과 해석·체험 코칭·선택 기록을 확장한 서버 기반 웹사이트입니다.

핵심 가치는 "운세를 맞힌다"가 아니라 **선택을 남기고 돌아본다**에 있습니다. 사주는 그 선택을 비추는 기준으로 쓰입니다.

## 실행

Node.js 22 이상, npm을 사용합니다.

```sh
npm ci
npm run build
npx wrangler d1 migrations apply dalbit-local --local
npm run dev          # http://localhost:8766
```

Render(또는 일반 Node 호스팅)용 서버는 별도로 띄웁니다.

```sh
npm ci && npm run build
npm start            # http://localhost:3000
```

### 테스트

```sh
npm test                      # 만세력·대운·코칭·안전 응답
node tests/storage.test.mjs   # 로컬 서버 실행 중에만
```

저장 테스트는 별도 세션에 테스트 기록을 만들고 지웁니다.

## 배포 (Render)

저장 API가 필요하므로 Static Site가 아니라 **Web Service**로 만듭니다. 정적 배포하면 첫 화면은 뜨지만 `load()`가 실패해 저장 기능이 전부 멈춥니다.

| 항목 | 값 |
|---|---|
| Service Type | Web Service |
| Branch | `main` |
| Runtime | Node |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm start` |
| Environment Variable | `NODE_VERSION=22` |

`package.json`에 `engines` 필드가 없어 호스팅 기본값이 적용되므로 `NODE_VERSION`은 생략하지 마세요. `render.yaml`이 위 값을 담고 있어 Blueprint로 연결하면 수동 입력이 필요 없습니다. 수동 생성하면 이후 `render.yaml` 변경이 배포에 반영되지 않습니다.

### 저장소와 플랜

기록은 세션별 JSON 파일로 보관됩니다. 현재 설정은 **free 플랜이라 디스크가 없고**, 파일은 인스턴스의 임시 저장소(`DALBIT_DATA_DIR` 미지정 시 `.data/`)에 쌓입니다. **재배포·재시작·유휴 슬립 때 상담과 기록이 사라집니다.** 시연에는 충분하지만 실제 사용자를 받을 때는 유료 플랜으로 올리고 persistent disk를 붙여야 합니다.

```yaml
    plan: starter
    envVars:
      - key: DALBIT_DATA_DIR
        value: /var/data/dalbit-saju
    disk:
      name: dalbit-saju-data
      mountPath: /var/data
      sizeGB: 1
```

Cloudflare Worker 설정(`wrangler.jsonc`, D1)도 함께 들어 있지만 Render 배포에는 쓰이지 않습니다. **둘 중 하나만 운영하세요.** 두 곳에 띄우면 보관함이 갈려 같은 사용자가 기기마다 다른 기록을 보게 됩니다.

## 구현한 기능

### 만세력

- 한국 음력·윤달 변환, 절기 시각 기준 년·월주, 현지 시간대, 선택적 지방평균태양시, 시간 미상 안내
- 출생지 66곳(국내 49·해외 17)을 지역별로 묶어 제공하며, 경도는 시청·도청 소재지 기준입니다. 지방평균태양시를 고르면 경도 차이가 실제로 시주를 가릅니다 — 목포(126.392°)와 포항(129.365°)은 약 12분 차이라, KST 05:24~05:32 출생은 각각 甲寅시·乙卯시로 갈립니다
- 지장간(여기·중기·본기), 십이운성, 공망, 신살(도화·역마·화개·천을귀인), 사주 각 자리의 십성
- **대운** — 년간의 음양과 성별로 순행·역행이 갈리고(양남·음녀 순행, 음남·양녀 역행), 대운수는 방향이 가리키는 절기까지의 일수를 3으로 나눠 구합니다

### 결과 해석

- `핵심 한 문장 → 강점·주의점 → 오늘의 행동 → 관심 주제별 해석 → 상세 근거` 순서
- 오행 균형을 오각형 차트와 개수·비율로 함께 표시
- 상세 명식·계산 근거·만세력·대운·연간 흐름을 모두 펼쳐 두고, 헤더 아래 고정된 바로가기(`주제 · 명식 · 만세력 · 대운 · 흐름`)로 이동합니다

#### 올해에서 오늘까지 (흐름)

세 줄 — 올해·이번 달·선택한 날 — 을 각각 **천간과 지지 양쪽**으로 읽습니다.

- **천간**: 일간과의 십성 열 가지(`FLOWSAY`)로 돌아볼 주제를 잡습니다. 예전에는 오행 관계 다섯 가지로만 눌러 써서 편인과 정인이, 비견과 겁재가 같은 문장을 받았습니다. 144개 날짜 표본에서 올해와 이번 달이 **글자 그대로 같은 문구**를 내던 비율이 17%였고, 지금은 8%(모두 십성까지 실제로 같은 경우)로 줄었습니다.
- **지지**: 일간 기준 십이운성으로 그 자리의 세기를 덧붙입니다(`FLOWGROUND`). 이전에는 지지를 아예 쓰지 않고 버려서 丙午와 丙子가 같은 줄을 냈습니다.
- **지장간**: 지지 속에 든 천간을 꺼내 각각의 십성까지 함께 읽습니다. 겉 천간이 같은 해와 달도 속이 다르면 다르게 보입니다.
- **신살**: 도화·역마·화개·천을귀인·공망을 그 지지 기준으로 판정해 해당될 때만 한 줄씩 붙입니다(`marksOf`).
- **충**: 흐름의 지지가 원국 지지와 마주 보면(여섯 칸 차이) 어느 기둥과 부딪히는지 함께 표시합니다.

한 줄은 최소 3줄(주제·지지·지장간)에서 최대 5줄(+신살·충)까지 늘어납니다. 가장 빽빽한 경우는 세 기둥이 같은 지지를 물고 신살과 충이 모두 걸릴 때로, 360px에서 15줄까지 확인했고 가로 넘침은 없습니다.
- 선택한 날 줄에는 **이 날 하루 자세히 보기**가 붙어, 일진 캘린더와 같은 하루 모달로 이어집니다.

천간과 지지, 충까지 합쳐 통째로 같은 줄이 나오는 경우는 같은 표본에서 2%이며, 이는 실제로 간지 관계가 같은 날입니다.

### 오늘

- 오행 관계에 따라 5종으로 갈리는 그림 (천간 10일 주기)
- 음력에서 유도한 달 위상
- **기운이 도는 시간** — 오늘 일지와 육합하는 지지의 시진. 밤 시진이 나오는 날은 잠들기 전후를 쓰라는 안내를 덧붙입니다
- **오늘 곁에 둘 색** — 일간을 생하는 오행(인성)의 빛깔
- **일진 이름** — `오늘은 붉은 개의 날, 병술일이에요` 형태. 천간의 오행 빛깔과 십이지 동물로 부르며, 만세력에서 바로 나오는 값이라 사람마다 같습니다

위 두 신호는 근거 문장을 함께 출력합니다. 등급이 아닙니다.

### 일진 캘린더

한 달치 일진이 내 일간에 어떻게 걸리는지를 달력으로 펼칩니다. 날짜를 누르면 그날의 점수가 **어떻게 나왔는지 항목별로** 보여줍니다.

| 항목 | 값 | 배점 |
|---|---|---|
| 기본 | — | 20 |
| 일간과의 관계 | 편인 | +30 |
| 십이운성 | 묘 | +14 |
| **합계** | | **64점** |

날짜를 누르면 그날의 전체 판독이 전면 시트로 열립니다 — 점수와 헤드라인, `총운`, `오늘의 신호`(기운이 도는 시간·곁에 둘 색·이날의 결), **`합과 충으로 인한 변화`**(일진이 원국의 어느 자리를 치는지 — 천간충은 십성 그룹으로, 지지충은 자오·축미 같은 짝 이름으로), **`12신살과 운성으로 보는 하루`**(십이신살 열둘과 십이운성), 그리고 점수 내역입니다. 충이 없는 날에는 없다고 적습니다. 본문은 십성·십이운성·신살을 평범한 말로 옮긴 것이라 **날짜를 눌러도 외부 호출이 없습니다.** 시트에서 바로 그 날짜로 선택 기록을 남길 수 있습니다.

배점표는 `src/constants.js`의 `TENSCORE`·`STAGESCORE`에 그대로 있고, 천을귀인 +12·공망 −10이 더해집니다. 무작위 요소가 없어 같은 입력은 항상 같은 값이며, 테스트가 `점수 = 기본 + 항목 합`을 고정하고 있습니다. 숨은 항이 생기면 실패합니다.

### 택일

무엇을 정할지 고르면(이사·개업·계약·혼인·여행·치료) 그 달에서 맞는 날을 골라줍니다. 근거는 **건제십이신**(월건과 같은 지지의 날이 建, 거기서 차례로 돕니다)과 **황도흑도**이고, 이사에는 손 없는 날을 함께 봅니다. 날짜마다 어떤 항목이 몇 점이었는지 붙여 보여줍니다.

월지와 일지만으로 정해지는 값이라 **사주와는 별개이며 누구에게나 같습니다.** 절입일에는 월건과 일지가 같이 한 칸 나아가 같은 건제신이 이틀 겹치는데, 통서의 규칙 그대로입니다.

## 계산에 무엇이 개입하지 않는가

해석 문구는 규칙 기반 문장이지만, **만세력과 모든 수치는 순수 산술**입니다.

- 엔진(`engine.js`·`constants.js`·`time.js`)에 AI/LLM 호출, `fetch`, `Math.random`, `Date.now`가 한 건도 없습니다. 의존성은 달력·날짜 라이브러리 네 개뿐입니다.
- 네트워크 인터페이스를 제거한 상태(`unshare -rn`)에서 실행해도 같은 결과가 나옵니다.
- 같은 입력은 언제나 같은 출력입니다. 별개 프로세스 6회 실행의 SHA-256이 모두 일치합니다.
- 일주를 **율리우스 적일(JDN)로 독립 계산**해 대조하면, 1901~2024년에 걸친 64개 날짜가 전부 일치합니다. 기준점 `1900-01-01 = 甲戌`(JDN 2415021)도 실제 만세력과 같습니다.
- 일진 이름은 다른 사주 서비스와 같은 값을 냅니다. 2026-09-09를 양쪽 모두 `붉은 개의 날, 병술일`로 부릅니다.

### 상담

`CAFE24_LLM_API_KEY`가 설정되면 카페24 LLM Router 상담(기본 `cafe24/auto`)이 켜지고, 없으면 아래 규칙 기반 코칭으로 자동 폴백합니다. 화면의 문구도 함께 바뀌므로 어느 쪽이 답하는지 사용자가 오인할 일이 없습니다.

- 키는 서버에만 둡니다. 브라우저는 `/api/coach`만 호출합니다.
- **위기·의료·재무 질문은 모델에 보내지 않습니다.** 기존 `safety()`가 먼저 걸러 정해진 안내를 그대로 답합니다.
- 규칙 기반 답을 **먼저 만들어 두고** 호출합니다. 키가 없든 호출이 실패하든 사용자는 늘 답을 받습니다.
- 세션당 분당 12회로 제한하고, 교차 출처 요청은 차단합니다.
- 명식은 계산된 값만 길이·모양을 강제해 보냅니다. 자유 문장은 대화 쪽에만 실립니다.

#### 잘린 답과 형식 어긋남

라우터 연결은 성공하는데 답이 문장 중간에서 끊기거나 `사주 관점` 제목이 통째로 빠지는 일이 있었습니다. `finish_reason`을 읽지 않았던 것이 원인입니다.

- **이어받기.** `finish_reason === 'length'`면 토큰이 모자라 끊긴 것입니다. 같은 요청을 처음부터 다시 돌리면 같은 자리에서 또 끊기므로, 받아둔 부분을 `assistant` 차례로 되돌려주고 그다음부터 쓰게 합니다. 최대 두 번까지 이어받고, 그래도 끊기면 `truncated: true`로 알립니다.
- **겹침 제거.** 이어쓰기가 앞말을 되풀이하는 모델이 있어, 가장 긴 겹침(여섯 글자 이상)을 찾아 잘라내고 붙입니다.
- **제목 검사.** 세 제목이 각각 한 줄에 그대로 서 있는지 봅니다(본문에 우연히 섞인 같은 말은 세지 않습니다). 빠졌으면 형식을 못박아 한 번만 다시 받고, 그래도 어긋나면 502로 돌려 규칙 코칭이 답하게 합니다.
- **대운 판독**도 같은 이어받기를 씁니다. JSON은 한 글자만 잘려도 통째로 못 읽기 때문에 오히려 더 필요합니다.
- **관측.** 응답에 `shape: {model, finishReason, truncated, continuations, sections}`가 실리고, 서버는 `LLM coach model=… finish=… continuations=…` 형태로 로그를 남깁니다. Render 로그에서 바로 보입니다. `model`은 라우터가 **실제로 고른** 모델이라, `cafe24/auto`가 무엇으로 풀렸는지 여기서 확인합니다.

이어쓰기 조각은 앞 공백을 지우지 않고 붙입니다. 다듬기를 조각마다 하면 `여기서` + ` 끊겼다가`가 `여기서끊겼다가`로 붙어버리기 때문입니다.

### 대운 판독

결과 화면의 대운 아래에서 여덟 구간을 한 편의 서사로 읽습니다. `/api/epic`이 JSON 출력 지시와 서버 검증을 거쳐 제목·캐치프레이즈·세 구간·맺음으로 돌려줍니다.

원형은 빌려오지 않았습니다. **십이운성 열두 단계(장생→목욕→관대→건록→제왕→쇠→병→사→묘→절→태→양)가 이미 생애의 부침을 담고 있고**, 그건 지어낸 상징이 아니라 명식에서 계산된 값입니다. 오르는 자리는 쥐는 시간, 기우는 자리는 놓는 시간, 비어 있는 자리는 보이지 않게 준비되는 시간으로 읽되 어느 구간도 길흉으로 판정하지 않습니다.

명리 용어는 `pillar` 필드에만 씁니다 — 본문에 십성·오행이 새지 않는지 테스트가 확인합니다. 예언·건강·수명·금액·특정 연도 예측은 금지하고, 주어는 언제나 사용자 본인입니다. 상담보다 훨씬 비싼 호출이라 10분에 네 번으로 따로 제한합니다.

상담 중 자연스럽게 기록을 남길 수 있습니다. 선택이 구체적으로 드러나면 모델이 "이 선택, 기록해둘까요?"라고 묻고, 답변 끝에 보이지 않는 `<기록>{...}</기록>` 블록을 붙입니다. 서버가 이 블록을 본문에서 떼어내 제목·주제·기대를 검증한 뒤 돌려주고, 사용자가 `웅`·`ㅇㅇ`처럼 수긍하면 선택 화면에서 만드는 것과 **같은 모양의 기록**이 남아 7일 뒤 회고로 이어집니다. 수긍 판정은 클라이언트에서 하므로 모델을 한 번 더 부르지 않고 즉시 반응하며, 같은 말에는 늘 같게 동작합니다. 거절하면 남기지 않고, 관계없는 말을 하면 제안은 조용히 사라집니다.

### 대화 캡처 (공유하기)

+ 시트의 **대화 캡처**로 들어갑니다. 카카오톡과 같은 **범위 선택**입니다 — 하나씩 골라 담는 것이 아니라 시작 말풍선과 끝 말풍선을 찍으면 사이가 전부 담깁니다.

- 아무것도 고르지 않은 채 시작해 `캡처를 시작할 말풍선을 선택해 주세요.`부터 묻습니다. 두 말풍선을 찍으면 그 사이가 모두 선택됩니다(거꾸로 찍어도 됩니다).
- **선택 해제**를 누르면 처음으로 돌아가고, 안내가 `캡처를 시작할 말풍선을 선택해 주세요.` → `캡처를 종료할 말풍선을 선택해 주세요.` → `N개 선택됨` 순으로 바뀝니다.
- 아래 줄에 **복사 · 공유 · 저장 · 취소**가 있습니다. 복사는 PNG를 클립보드에 넣고, 공유는 시스템 공유 시트를 엽니다. 둘 다 기기가 지원하지 않으면 버튼을 아예 감춥니다 — 눌렀을 때 딴 일을 하는 버튼을 두지 않기 위해서입니다(데스크톱 크로미엄에서는 공유가 빠지고 복사·저장만 보입니다).

`html2canvas` 같은 DOM 복사 라이브러리를 쓰지 않고 `src/capture.js`에서 캔버스에 직접 그립니다. 그래서 번들이 늘지 않고, 화면에 떠 있는 것(하단 내비·배경 멈춤 토글·저장 배지)이 캡처에 섞여 들어갈 일도 없습니다. 머리말의 도령 얼굴·말풍선·시각·꼬리말을 2배 해상도로 그리며, 글꼴은 화면과 같은 마루 부리를 `document.fonts.ready` 이후에 씁니다.

저장은 `navigator.canShare({files})`가 되는 기기에서는 시스템 공유 시트를, 아니면 바로 내려받기로 떨어집니다.

Render에서는 Environment Variables에 `CAFE24_LLM_API_KEY`를 추가하면 켜집니다(`LLM_ROUTER_KEY`도 인식합니다). 기본 모델은 자동 라우팅을 사용하는 `cafe24/auto`이며 `CAFE24_LLM_MODEL`로 카페24 모델 목록의 ID나 `@preset/이름`을 지정할 수 있습니다. Base URL을 별도로 운영하는 경우에만 `CAFE24_LLM_BASE_URL` 또는 `LLM_ROUTER_URL`을 설정하세요.

### 상담 화면

말풍선이 차지하는 자리를 최대한 남깁니다. 390px에서 메시지 영역이 패널의 56%였던 것을 **72%**로 늘렸습니다.

- **입력칸**은 한 줄(46px)에서 시작해 쓰는 만큼만 자라고(최대 132px), 보내고 나면 다시 한 줄로 돌아옵니다. 예전에는 `rows=2`에 `min-height:64px`이라 한 줄을 써도 77px을 먹었습니다.
- 답변마다 붙는 도구는 **복사·저장** 둘뿐입니다. 시각과 같은 줄에 글자 링크로 놓입니다(`07:32 복사 저장`). 캡처는 말풍선마다 있을 이유가 없어 + 시트의 **대화 캡처** 한 곳으로 모았습니다. 탭 영역은 44px을 지킵니다.
- 이 줄은 말풍선 바깥, 산수화 배경 위에 얹힙니다. 글자를 감춘 채 그 자리를 찍어 실제 배경 픽셀로 재어 보니 옅은 회색(`#7a8579`)은 대비가 **2.00–3.45:1**로 12px 본문 기준 WCAG AA(4.5:1)에 못 미쳤습니다. 시각은 중성 먹색(`#3f4a43`), 동작은 청록(`--teal`)으로 바꿔 **4.81–8.50:1**이 되었습니다. 밝기 대신 색상으로 위계를 냈기 때문에 동작이 시각보다 무거워 보이지 않습니다.
- **+ 버튼**이 입력칸 왼쪽에 있습니다(카카오톡과 같은 자리). 누르면 시트가 열리며 **대화 캡처 · 이전 상담 · 새 상담 · 선택 기록**과 주제 칩이 모두 나옵니다. 열리면 +가 ×로 돌아가고, 메시지를 보내거나 항목을 고르거나 화면을 옮기면 닫힙니다.
- 덕분에 입력줄은 늘 한 줄입니다. **주제 칩은 첫 대화 전에만 입력칸 위에 나와 있고**, 대화가 시작되면 시트 안으로 들어가 50px을 돌려줍니다. 처음 온 사람은 +를 찾지 않아도 시작 지점이 보이고, 대화 중에는 화면을 차지하지 않습니다. 두 곳에 동시에 두지 않으므로 같은 칩이 겹쳐 보이는 일은 없습니다.
- 시트의 **대화 캡처**가 캡처로 들어가는 유일한 길입니다. 인사말 하나뿐일 때는 캡처할 대화가 아니라서 막습니다.
- 같은 취지의 경고가 화면 위(상담 안내)와 아래(`chat-foot`)에 따로 있었습니다. 위 안내 한 곳으로 합쳤습니다. 요약 줄(`상담 안내 · 전문적 판단을 대신하지 않습니다`)은 늘 보입니다.

### 체험 코칭 (폴백)

규칙 기반입니다. 사용자가 쓴 문장에서 조건(보상·안정성·조직 규모·성장·시간·사람·거리·관계 거리·지출 구조)과 숫자를 뽑아, 그 조건을 비교 가능하게 만드는 확인 항목으로 답합니다. 답변은 `사주 관점 / 현실 확인 / 오늘 할 일` 세 부분으로 나뉩니다.

같은 말을 되돌려주지 않도록: 사주 해석은 한 번만 말하고 이후 참조하며, 조건은 최신순 3개로 제한하고, 오늘 할 일은 회전합니다.

#### 듣기 단계

첫 마디가 늘 결정을 들고 오지는 않습니다. "요즘 잠을 못 자요"에 `진로 이야기를 함께 정리해볼게요. 지금 생각하는 선택지는 무엇이고…`라고 답하던 것을 고쳤습니다. 두 가지 문제가 겹쳐 있었습니다.

- 첫 메시지를 무조건 비교할 결정으로 취급했습니다. 이제 `smallTalk()`이 잠·피로·불안·우울·외로움·답답함과 단순 인사를 먼저 가려내고, 그럴 때는 `listen` 단계로 받아 문맥을 비워 둔 채 한 번 더 듣습니다. 결정거리가 나오면 그때 기존 흐름으로 넘어갑니다.
- 주제를 **사용자가 말하지 않았는데** 단정했습니다. 프로필에 적어둔 관심사를 끌어와 "진로 이야기를"이라고 붙였던 것인데, 지금은 사용자의 말에서 주제가 실제로 잡혔을 때만 이름을 부릅니다.
- 수면 이야기에는 "오래 이어진다면 수면은 사주가 아니라 진료로 푸는 쪽이 맞습니다"를 함께 답합니다.

주제 판정의 부분 문자열 오탐도 같이 고쳤습니다. `A회사랑 B회사`의 **회사랑**이 `사랑`에 걸려 연애로, `아이디어`의 **아이**가 가족으로 분류되던 문제입니다.

### 선택 기록

- 선택 프리셋과 직접 입력, 다섯 단계 확신도(성격 검사식 원형 버튼), 1·3·7일 후 회고 예약
- 감정 5단계와 결과 3택으로 회고, 상세·수정·삭제
- 최근 보름의 달 흐름을 보여주는 나침반 다이얼
- 월간 요약과 확신도별 결과 비교("확신이 낮을 때 결과가 더 좋았다" 형태)

### 저장과 개인정보

서버 저장, 세션별 데이터 분리, 충돌 감지, 개인정보 전체 삭제, JSON·텍스트 내보내기.

### 화면

모바일 우선, 데스크톱에서는 결과와 상담을 2열로 배치합니다.

글꼴은 **마루 부리**로 통일했습니다. 네이버 배포본을 KS X 1001(한글 2,350자)과 라틴·문장부호로 서브셋해 `assets/fonts/`에 직접 호스팅하므로 외부 폰트 요청이 없습니다 — 3종(400·600·700) 합계 410KB로, 서브셋 전 891KB에서 절반 이하입니다.

마루 부리에는 **한자와 호환 자모가 들어 있지 않습니다**(원본 글리프 12,341자 중 CJK 0자). 명식의 간지(乙亥 辛巳 …)는 `--font` 스택의 명조 폴백(AppleMyungjo·Nanum Myeongjo·바탕)이 그립니다. 부리 계열끼리라 나란히 놓았을 때 이질감이 적습니다. KS X 1001 밖의 드문 음절도 같은 폴백으로 갑니다. 전통 이미지는 결과 화면과 나침반 두 곳에 집중해 씁니다.

## 성능

클라이언트 번들은 만세력 계산부를 분리해 지연 로드합니다.

| | 이전 | 현재 |
|---|---|---|
| 초기 진입 | 473KB / gzip 148KB | **118KB / gzip 38KB** |
| 만세력 청크 | 항상 | 결과 화면 진입 시 (363KB) |

- `src/constants.js`, `src/time.js` — 만세력 의존이 없는 조회표와 날짜 헬퍼. 첫 화면과 생년월일 입력이 이것만으로 그려집니다.
- `src/engine.js` — 별도 엔트리(`/engine.js`)로 빌드됩니다. 실패한 dynamic import는 브라우저 module map에 URL 기준으로 영구 캐시되므로, 재시도가 실제로 동작하려면 URL을 바꿀 수 있어야 합니다(`?r=N`).
- Worker 자산 목록은 `dist/client` 전체를 훑어 생성되므로 청크가 자동 포함됩니다.

## 명확한 범위

자동 푸시·이메일·결제는 연결하지 않았습니다. 상담은 `CAFE24_LLM_API_KEY`가 있을 때만 실제 AI로 동작하고, 없으면 규칙 기반이며 화면에도 "체험 코칭"으로 표시합니다. 회고 알림은 캘린더 파일로 제공하며, 가져오기를 완료해야 일정이 등록됩니다. 앱이 직접 알림을 보내지는 않습니다.

서버 보관함은 HttpOnly 쿠키로 연결하며 기기 간 계정 동기화·복구를 지원하지 않습니다. 쿠키를 삭제하기 전에 필요한 데이터를 내보내야 합니다. 서버 운영자가 접근할 수 없는 종단간 암호화는 아닙니다.

사주 해석은 자기 이해용 전통 해석으로 미래나 성격의 과학적 진단이 아닙니다.

오행 비율은 대표 오행 개수이며 용신·신강/신약 판정이 아닙니다. 년·월주는 실제 시각을 UTC+8 계산표로 비교하고, 일·시주는 선택한 현지 시각 또는 경도 보정 시각을 사용합니다. 자정 일주 교체를 채택합니다. 지방평균태양시는 균시차까지 반영한 진태양시가 아닙니다. 서머타임 중복 시각은 모호하게 추정하지 않고 입력 오류로 표시합니다.

대운수는 3일을 1년으로 보는 방식이며, 절입 시각까지 분 단위로 반영하는 유파와는 한 살 차이가 날 수 있습니다. 십이운성과 신살은 유파마다 채택 범위와 기준 자리(년지·일지)가 다릅니다. 이 구현은 년지와 일지를 함께 봅니다. 어느 항목도 길흉 등급이 아니라 명식에서 읽히는 자리 이름입니다.

일진 캘린더의 점수는 위 항목에 배점을 매겨 더한 값입니다. 배점 자체는 이 구현이 정한 것이라 다른 서비스의 점수와 같을 수 없고, 좋고 나쁨의 판정도 아닙니다. 총점만 보고 판단하지 않도록 화면에서 항목과 배점을 늘 함께 보여줍니다.

성별은 대운의 순행·역행을 가르는 데에만 사용하며, 해석 문구는 성별로 달라지지 않습니다. 성별을 입력하지 않으면 방향을 추측하지 않고 대운을 계산하지 않습니다.

## 게시 상태

기존 Sites 프로젝트 ID는 `.openai/hosting.json`에 유지되어 있습니다. 현재 연결 계정에서 기존 사이트를 찾지 못해 해당 경로로는 게시하지 않았습니다. 새 사이트를 임의로 생성하지 않았습니다.

이미지는 개별 WebP로 제공하며 초기 HTML에 삽입하지 않습니다. `src/generated-assets.js`는 빌드 시 Worker용 자산으로 생성되며 브라우저 HTML에는 포함되지 않습니다.
