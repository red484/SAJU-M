# 노트 보관함 통신 범위

2026-11-05. iOS 달빛 노트와 웹의 `?app=note` 미리보기는 `/api/journal?view=note`를 사용한다. 일반 웹·Android·토스의 기존 API 동작과 계정 소유권·연령 확인은 유지한다.

- 응답은 버전과 노트용 보관함이다. 프로필은 null, 대화·저장 답변은 빈 배열이며, 기록은 `NOTE_RECORD_FIELDS`의 선택·회고 필드만 제공한다. 명리 조언·임의 웹 메타데이터는 제외한다. 알 수 없는 보기 이름은 400으로 거절한다.
- 클라이언트도 같은 투영을 저장 전에 적용한다. 서버에 숨겨야 할 데이터를 받은 뒤 화면에서만 가리는 방식이 아니다. 백그라운드 회고 알림 조회에도 적용한다. 노트에서는 출생 프로필을 포함하는 이전 웹 보관함 가져오기를 실행하지 않는다.
- 서버는 기존 보관함을 읽고 버전을 대조한 뒤, 기록에 속하는 변경만 합친다. 기존 프로필·대화·저장 답변과 기록별 보이지 않는 필드는 유지한다. 마지막 저장에도 저장소의 원자적 버전 검사를 적용하므로 중간 웹 저장이 있으면 409가 된다. 기존 클라이언트 3방향 병합은 투영된 기록끼리 비교하며 같은 기록 충돌은 덮어쓰지 않는다.
- 기록 삭제는 그 기록만 공용 목록에서 제거한다. 내보내기는 노트가 받은 내용만 담는다. 노트 보기 경로의 DELETE는 거절한다. 계정 탈퇴·전체 삭제는 별도의 명시적 경로로 공용 계정 데이터까지 삭제하므로 노트 삭제 확인에 그 범위를 명시한다.

이는 데이터 통신 최소화다. 별도 DB·계정이나 iOS 기기에 대한 보안 인증 경계를 만든 것이 아니다. 동일한 인증의 일반 웹 경로는 기존 전체 보관함을 조회할 수 있으며 이전 클라이언트도 호환된다. 선택 기준·행동·회고와 기록 연결 ID, 자유 입력 안에 이용자가 적은 정보는 계속 기록으로 공유된다. 연령 확인·로그인·통계 등의 별도 처리도 그대로다. ‘iOS는 개인정보 수집 없음’으로 해석하면 안 된다.

## 검증

`tests/note-journal.test.mjs`는 파일 저장소와 실제 PostgreSQL 호환 PGlite에 HTTP로 요청한다. 프로필·대화·답변·조언 미노출, 저장 시 기존 필드 유지, 두 로그인 연결의 웹 변경 뒤 충돌·재시도, 기록 삭제·전체 삭제와 잘못된 프로필 주입을 확인한다. 클라이언트 직렬화에서 숨겨진 데이터가 전송되지 않는지, 기본 웹 호출이 유지되는지도 검사한다. 네이티브 테스트는 노트의 백그라운드 조회 URL을 확인한다.

실제 고객 보관함을 수정·삭제하거나 보존·백업 설정을 변경하지 않는다. 실기기·실제 스토어 제출은 별도 검증이다.

별도 로컬 브라우저의 노트 미리보기에서 실제 응답·저장 요청에 시험용 웹 비공개 표식이 없음을 확인하고, 회고 저장 뒤 일반 웹 API에서 원래 프로필·대화·답변·조언·메타데이터가 유지됨을 확인했다. 시험 보관함은 정리했다.
