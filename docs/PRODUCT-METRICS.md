# 선택형 이용 통계 확인

운영 백엔드에서 `sudo docker exec saju-backend node server/product-metrics-report.mjs`를 실행한다. 개발 DB는 환경에 `DATABASE_URL`을 설정한 뒤 `npm run report:product`를 사용한다. DB 연결 문자열이나 인증 정보를 보고서·명령행 출력에 넣지 않는다.

## 집계 기간

- 기준 날짜와 원본 일별 집계를 하나의 DB 조회로 읽는다. 한국 자정에 실행돼도 서로 다른 날짜를 기준으로 계산하지 않는다.
- `periods.today`는 한국 날짜다. `today` 건수는 아직 끝나지 않은 오늘의 부분 집계다.
- `last7`은 오늘을 제외한 완료된 7일, `previous7`은 그 직전 7일이다. `change7`은 `last7 - previous7`의 건수 차이다. 각 기간의 시작·종료 날짜를 함께 출력한다.
- `last30`은 오늘과 이전 29일이다. 미래 날짜와 기간이 지난 행은 DB에 남아 있어도 보고서에서 제외한다. 보고서 실행은 행을 추가·수정·삭제하지 않는다.

예를 들어 기준 날짜가 2026-11-04이면 최근 7일은 10-28~11-03, 직전 7일은 10-21~10-27이다. 11-04의 일부 집계를 11-03의 하루 전체와 비교하지 않는다.

## 출력과 해석

- `overall`: 동작별 전체 채널 합계. 수집하지 않은 동작도 0으로 표시한다.
- `channels`: 해당 30일에 관측된 채널별 같은 집계. 비어 있으면 관측된 채널이 없는 것이다.
- `rows`: 기존 한국 날짜·채널·동작별 원본 합계. 개인정보나 개별 이용 이력이 아니다.
- 건수와 증감은 큰 정수의 정확도를 유지하기 위해 문자열로 출력한다. `change7`은 음수일 수 있다.
- `no_observed_events`는 수집된 합계가 없다는 뜻이다. 이용자가 없거나 오류가 없었다는 증거가 아니다. 선택에 동의하지 않은 이용, 전송 실패와 실제 동작 미발생을 구분할 수 없다. DB 오류는 실패로 종료하며 빈 통계로 대체하지 않는다.

확인할 동작은 상품 안내 열기·상품 조회 실패·결제 시작·지급·복원, 상담별 첫 AI 답변·선택 저장·회고 저장이다. 상품 조회 실패 건수가 나타나면 해당 채널의 상품 조회를 점검하고, 선택·회고 저장 건수는 기능 이용의 관측 자료로 활용한다. 실패 건수 0만으로 기능 정상이나 테스트 완료를 판단하지 않는다.

**전환율·매출·고유 사용자 분석이 아니다.** 동의한 기기의 동작 건수만 모으며 개인·주문 식별자가 없어 행동의 순서와 같은 사람의 재방문을 연결할 수 없다. 결제 시작과 지급의 차이를 결제 실패나 환불 건수로 해석하지 않는다. 재시도·복원·다른 기기와 시점이 다른 동작이 섞일 수 있다. 웹은 현재 상품 미리보기이므로 결제 시작·지급을 기대하지 않는다. 모집 문구의 동의율이나 개선의 인과 효과도 이 자료로 계산하지 않는다.

이 개선은 기존 합계의 읽기·표시만 바꾼다. 수집 항목·동의 방식·30일 보존기간과 공개 API는 변경하지 않는다. 향후 개인별 퍼널이나 신규 식별자를 추가하려면 수집 목적·동의·보존 범위를 다시 검토해야 한다.
