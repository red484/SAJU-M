# 프론트엔드–백엔드 경계

## 원칙

| 프론트엔드 | 백엔드 |
|---|---|
| 사주·달력·택일을 결정적으로 계산 | 입력 형식과 요청 출처를 검증 |
| 계산 결과와 기록을 화면에 표현 | 기록을 revision과 함께 영구 저장 |
| `/api/*` 상대 경로만 호출 | Cafe24 비밀 키를 보관하고 AI 호출 |
| 실패 중에도 사용자의 입력을 유지 | AI/DB 오류를 정규화해 상태 코드로 응답 |
| 서버가 준 revision을 그대로 반환 | 충돌 시 409로 거절하고 덮어쓰지 않음 |

브라우저가 DB에 직접 연결하거나 Cafe24 키를 보유해서는 안 된다. 백엔드는 사주 계산값을 새로 만들어 프론트 결과와 경쟁하지 않는다.

## 신뢰 경계

- 브라우저가 보내는 계산 결과와 JSON은 모두 비신뢰 입력이다.
- HttpOnly 쿠키 원문은 서버만 읽으며 DB에는 해시만 남긴다.
- 같은 출처가 아닌 쓰기·AI 요청은 `403`으로 거절한다.
- 프록시의 HTTPS·Host 헤더는 Lightsail Nginx 설정과 함께 관리한다.
- 인증은 아직 없으므로 익명 쿠키는 계정이나 본인 확인 수단이 아니다.

## 계약 변경 절차

1. 요청/응답 예시와 오류 코드를 문서에 먼저 반영한다.
2. 백엔드가 구버전 요청을 수용할 수 있는지 판단한다.
3. 프론트 API 모듈과 서버 route 테스트를 함께 수정한다.
4. DB 변경이면 새 migration을 추가한다.
5. build, test, smoke, readiness를 확인한다.
