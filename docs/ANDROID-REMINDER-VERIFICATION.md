# Android 회고 알림 검증 (2026-11-05)

## 수정

- 알림 권한을 거부한 뒤 OS에서 허용하고 기존 WebView로 돌아오면 예약이 비어 있던 문제를 확인했다. 앱 활성화 때 마지막으로 읽은 보관함과 이 기기의 알림 선택으로 다시 동기화한다. 이 경로에서는 권한 팝업을 요청하지 않는다. 열린 기록의 예약 상태도 갱신한다.
- 설치된 LocalNotifications 8.3.1의 기본 정확한 알람 예약은 특별 접근 권한이 없을 때 시스템 설정을 자동으로 열었다. Android에는 `isExactNotification: false`를 명시해 일반 예약으로 처리한다. 새 Android 권한을 추가하지 않았다.
- 알림 안내는 저녁 8시를 목표로 예약하되 기기 설정에 따라 지연될 수 있다고 표시한다. [Capacitor 공식 API](https://capacitorjs.com/docs/apis/local-notifications)의 일반·정확한 알림 구분을 따른다.

## 검증 범위

다른 작업의 기기에 영향을 주지 않도록 별도 Android 16/API 36 에뮬레이터와 익명 시험 보관함을 사용했다. 실계정 로그인·AI 호출·구매는 하지 않았다.

1. 기존 운영 코드에서 권한 거부→백그라운드→OS 권한 허용→복귀 후 권한은 허용인데 예약 0건인 상태를 재현했다.
2. 후보 웹 번들을 디버그 WebView에 시험용으로 공급해 같은 절차에서 기록 1건의 회고일 20:00(+09:00) 일반 예약을 확인했다. 복귀 중 WebView를 새로고침하지 않았다.
3. 실제 네이티브 플러그인으로 같은 시험 기록 알림을 15초 뒤로 예약하고 홈으로 나간 뒤 `am kill`로 백그라운드 앱 프로세스를 종료했다. 실제 OS 알림이 도착했고 알림창에서 눌러 앱이 다시 열리며 해당 기록 편집창이 열리는 것을 확인했다. Android의 강제 중지(`force-stop`)는 사용하지 않았다. 이 단축 예약은 실제 20시를 기다린 시험이 아니다.
4. 자동 테스트는 권한 없는 복귀 시 팝업 미요청, 기기 선택 해제·전체 정리 후 예약 미복원, 비활성 이벤트 무시, Android 일반 예약 옵션을 검사한다.

HAINDY는 저장된 인증 만료로 UI 실행이 불가능해 전용 ADB와 디버그 WebView로 검증했다. 제품 코드에 시험용 인터페이스를 추가하지 않았다.

## 남은 한계

- 두 **실기기**의 동일 계정·서로 다른 알림 선택은 아직 검증하지 않았다.
- 아래 후속 수정으로 복귀 시 서버 기록도 조회한다. 실제 두 기기의 OS 예약 반영 검증은 남는다.
- 실제 회고일 20시 자연 수신, 제조사 절전·Doze·재부팅, iOS 실제 OS 수신은 남는다.
- 이 수정은 운영 웹을 여는 Android 앱에 웹 배포로 반영된다. 새 앱 스토어 빌드 제출이나 승인 완료를 뜻하지 않는다.

## 후속: 다른 기기에서 수정한 기록 반영

앱 활성화 시 마지막 로컬 기록으로 권한 변경부터 반영한 뒤 기존 `/api/journal`을 읽어 최신 저장 기록으로 알림만 재조정한다. Android의 알림 선택은 여전히 해당 기기의 설정만 사용하고, iOS 노트의 기존 자동 예약도 유지한다. 기록 폼·상담 화면·초안과 앱의 편집 모델은 이 조회로 교체하거나 다시 렌더링하지 않는다.

- 다른 기기에서 회고일을 바꾸면 새 날짜로 예약하고, 회고 완료·기록 삭제 시 예약을 해제한다.
- 네트워크·서버 오류 또는 올바르지 않은 응답은 빈 보관함으로 간주하지 않고 마지막 예약을 유지한다. 인증 만료(401)는 해당 보관함의 예약을 해제한다. 기기별 알림 선택은 유지한다.
- 시작 시 보관함을 읽기 전에는 추가 조회하지 않는다. 새 저장·전체 정리·보관함 교체 후 늦게 끝난 읽기는 버린다. 재진입 조회에는 기존 API의 제한 시간을 적용하며 새 서버 쓰기를 하지 않는다.
- `node tests/native-shell.test.mjs`에서 실제 알림 모듈을 번들하고 OS 플러그인·HTTP 응답만 대역으로 바꿔 날짜 변경·완료·삭제·기기별 선택·통신 실패·비정상 응답·401·늦은 응답의 경합을 검증한다. 기존 편집 데이터가 바뀌지 않는지도 검사한다.

앱이 닫혀 있거나 오프라인인 동안 다른 기기의 변경을 실시간으로 받을 수는 없다. 서버의 변경을 읽은 뒤 예약이 반영되는 것과 OS가 실제 알림을 배달하는 것은 별도 검증이다. 이번 후속 작업에서는 실기기 검증을 진행하지 않았다.
